수집 장비·기간·분석 원리와 실제 연동 API를 구분해 살펴봅니다. 현재 구현과 향후 적용을 분리하며, 확인되지 않은 AI 성능을 주장하지 않습니다.

휴대폰 기본 워치 선택 연동 전문검사 별도 첫 28일 운영 설계

기기 조합부터 명확하게

공식 API는 데이터 접근 방법을 제공하지만, 착용·권한·기기 호환성·동기화 여부에 따라 실제 기록은 빠질 수 있습니다.

휴대폰만

지원 걸음센서, 앱 실행 중 GPS, 직접 녹음·인지과제, 본인·가족 입력. 휴대폰 미소지 시간이나 자동 수면 측정까지 확보하지는 못합니다.

기본 수집 경로 · 일부 코드 존재

휴대폰 + 지원 워치

갤럭시 워치6·삼성 헬스 → Health Connect 또는 애플워치 SE 2세대·Apple Health → HealthKit. 수면 세션·걸음수·심박 기록의 사용자 허용 범위를 읽는 방식입니다.

공식 API 지원 · 낌새 연동 미완료

의료기관 검사 결과

혈압·혈액검사·인지검사·진단·MRI·PET 등은 검사기관에서 실제로 생성한 결과를 제출받아 연결합니다. 휴대폰과 워치만으로 만들어지는 값이 아닙니다.

외부 문서·기관 연계 분리

9개 데이터 분야: 무엇 · 왜 · 어떻게 · 언제

낌새의 Evidence·연구 데이터 명세를 기준으로 작성했습니다. ‘기간·빈도’는 첫 원사이클 운영 제안이며 치매 진단을 위한 검증된 최소기간이 아닙니다.

9개 분야 표시 중
01

위험요인 · 대상자

어떤 데이터

연령·성별·교육기간, 수축기혈압, BMI, 총콜레스테롤, 신체활동, CAIDE 점수. 당뇨·우울·청력/시력·흡연·사회관계는 추가 맥락.

왜

장기 위험요인을 일상생활의 최근 변화와 혼동하지 않기 위해.

어떤 기계 · 어떻게

휴대폰 설문 + 혈압계·체중계·건강검진 결과최초 등록 시 본인·보호자가 설문 입력. 혈압·체중은 별도 실측값, 콜레스테롤은 검사 결과지 수치만 입력. 검사 기록은 출처·일자를 따로 저장.

수집 기간 · 빈도

등록 시 1회, 측정·건강검진·상태 변경 시 갱신

휴대폰 입력 가능 · 검사 수치는 외부 측정 필수

한계 사용자가 입력한 값 ≠ 의료기관에서 확인한 값.

02

수면 · 생활리듬

어떤 데이터

총수면시간, 잠든/깬 시각, 수면 중앙시각, 날짜별 수면 규칙성·평소 대비 변화. 야간활동은 기기 제공 범위와 별도 측정법 확인.

왜

수면량과 수면 시간대의 지속적인 변화를 확인하기 위해.

어떤 기계 · 어떻게

갤럭시 워치6 + 삼성 헬스/Health Connect 또는 애플워치 SE 2세대 + Apple Health/HealthKit현재 낌새: 휴대폰에서 본인 수면시간 수동입력. 자동 방식: 워치가 기록한 수면 세션을 폰 건강저장소와 동기화한 뒤 사용자 권한으로 낌새 앱이 읽어 일별 저장.

수집 기간 · 빈도

매일 밤 기록 → 하루 1회 동기화, 첫 28일 이상

공식 건강 API 지원 · 낌새 워치 자동연동 미구현

한계 워치 착용·충전·동기화·권한이 없는 밤은 미수집으로 기록.

03

이동 · 외출 · 생활반경

어떤 데이터

관찰된 외출·위치 시각, 관찰구간 이동거리, 생활반경, 장소 다양성, 루틴 이탈, 개인 기준선 대비 변화.

왜

외출 감소, 생활권 축소와 반복 동선의 변화를 보기 위해.

어떤 기계 · 어떻게

GPS 지원 Android/iPhone + 위치권한휴대폰 위치 API로 시간·좌표의 동의된 관찰값을 취득하고 이동·체류 특징을 계산. 현재 낌새는 앱 전경 위치 관찰 중심이며 백그라운드 수집은 별도 구현·정책 검토가 필요.

수집 기간 · 빈도

가능한 관찰구간을 매일 누적, 28일 이상

위치 API 지원 · 전경 코드 존재 · 상시 수집 미완성

한계 휴대폰을 두고 외출하거나 앱·OS가 수집을 제한한 시간은 관측되지 않음.

04

활동 · 보행

어떤 데이터

걸음수, 관찰 가능한 활동·비활동 시간, 평소 대비 걸음 변화. 보행속도·보폭 변동성·이중과제 비용은 별도 정밀 측정 과제.

왜

일상 활동 저하와 정밀 보행 기능 변화를 구분해 관찰하기 위해.

어떤 기계 · 어떻게

휴대폰 걸음센서(Android TYPE_STEP_COUNTER / iOS CMPedometer), 선택적 워치걸음수는 네이티브 센서 API → 낌새 신호 저장. 현재 연결 코드 있음. 보행속도·변동성·이중과제는 휴대폰 소지만으로 자동 확정하지 않고 별도 과제·센서 처리 필요.

수집 기간 · 빈도

걸음수 매일 28일 이상; 정밀 보행은 주 1회 표준 과제 제안

걸음수 네이티브 연결 코드 · 정밀보행 미구현

한계 폰 미소지 시간은 전체 하루 활동으로 해석하지 않음.

05

음성 · 말하기

어떤 데이터

쉼 비율·평균 쉼시간, 발화속도, 운율 변동, 어휘 다양성, 추출 알고리즘 버전, 개인별 변화.

왜

발화의 속도·쉼·언어 사용 패턴이 평소와 달라지는지 관찰하기 위해.

어떤 기계 · 어떻게

Android/iPhone 마이크 + 앱 내 동일 녹음 과제사용자가 앱에서 직접 30~60초 녹음 → 녹음 시각·과제 ID 저장 → 음향 특징 추출. 어휘 다양성·분당 단어수 등은 별도 음성인식/언어 분석이 필요.

수집 기간 · 빈도

30~60초씩 주 3회 제안, 28일간 반복

능동 녹음·일부 음향특징 코드 · 언어 분석 미구현

한계 일반 통화 녹음·상시 주변 음성 자동수집 기능이 아님.

06

인지 · 화면 상호작용

어떤 데이터

과제 ID·시행 회차, 반응시간, 정답률, 완료 여부, 터치 간격, 오류 수, 반복 수행 변화.

왜

기억·주의·반응 양상의 개인별 경과를 추적하기 위해.

어떤 기계 · 어떻게

휴대폰 터치스크린 + 낌새 기억·주의·언어 과제앱 화면에서 사용자가 지정 과제를 수행 → 응답·시간·오류 이벤트를 저장. 현재 일부 과제 UI/기록 경로가 있으며 전 항목 일괄 자동측정이나 임상성능은 미검증.

수집 기간 · 빈도

회당 3~5분, 주 2~3회 제안, 첫 28일

휴대폰 실행 가능 · 코드 일부 구현 · 성능 미검증

한계 낌새 자체 과제 점수를 MoCA-K와 같은 전문검사 점수로 환산하지 않음.

07

일상기능 · 가족 확인

어떤 데이터

일상기능 영역, 변화 유형·정도, 독립생활 영향, 가족 확인 유무/시점/관계, 기분·복약 변경·사회활동.

왜

센서로 포착한 변화가 실제 생활기능 변화인지 확인하고 다른 원인을 파악하기 위해.

어떤 기계 · 어떻게

본인 휴대폰 + 보호자 휴대폰(웹/앱 입력)주간 체크리스트와 변화가 발생했을 때의 가족 입력. 낌새 내부 통화는 앱 내부 세션 로그만 사용. 일상사건은 누가 보고했는지 따로 기록.

수집 기간 · 빈도

가족 확인 주 1회 + 사건 발생 시, 28일 이상

수동입력 가능 · 낌새 내부 통화기록 코드

한계 일반 전화·카카오톡 전체 사용량 자동수집이 아님.

08

표준 임상 · 멀티모달

어떤 데이터

검증 인지/기능검사, 임상 단계, 혈액 바이오마커, 유전정보, MRI/PET/CSF 검사 참조, 액티그래피 결과.

왜

생활변화 기록과 실제 전문검사 결과를 동일 대상·시간축에서 비교하기 위해.

어떤 기계 · 어떻게

의료기관 검사지·진료기록·전문 검사 장비의료진이 수행한 검사 결과를 동의한 사용자가 결과지로 제공하거나, 향후 승인된 기관 연계로 수집. 원본·검사일·측정 방법·제공 출처를 구분.

수집 기간 · 빈도

실제 검사 시행일마다. 종단 연구의 6·12개월 재검사는 계획안

스키마 존재 · 의료기관 직접 자동연계 미확정

한계 휴대폰·워치 센서로 혈액/유전/MRI/PET/CSF 값을 만들 수 없음.

09

전문평가 · 확정 결과

어떤 데이터

전문 진단명, 검사명·원점수, 바이오마커 종류·결과, 검사 날짜, 문서 진위/검증 수준.

왜

낌새 관찰 변화와 후속 의료적 평가 결과를 연결해 연구 검증의 기준으로 삼기 위해.

어떤 기계 · 어떻게

의료진의 전문평가/진단서·검사 결과지자가 기입 / 원본 결과지 확인 / 의료기관 직접제공을 출처 수준별로 별도 저장. 진단의 주체는 의료진이고 낌새가 진단을 대체하지 않음.

수집 기간 · 빈도

기준 평가 시점 및 후속 실제 검사·진료 시점마다

데이터 구조·경로 존재 · 기관 검증·연계 미완료

한계 전문검사를 받지 않은 사용자는 결과가 비어 있는 것이 정상.

별도 확장 후보: 심박수 — 갤럭시 워치·애플워치의 심박 기록은 Health Connect / HealthKit을 통해 접근할 수 있습니다. 다만 이는 현재 9개 연구 변수군에 독립 항목으로 확정된 것이 아니므로 생리적 맥락 데이터 후보로 분리합니다. 심박수 자체를 치매 진단 지표로 표시하지 않습니다.

28일 원사이클: 실제로 한 바퀴 도는 순서

현재 앱의 수집·기준선 코드에 맞춘 운영 설계입니다. 사람에게서 28일 원사이클이 완주·검증되었다는 의미가 아닙니다.

STEP 01

등록 · 동의 · 장비 연결

사용자·보호자 관계 확인, 입력 기초 위험요인 등록, 휴대폰 센서권한, 선택 워치 건강기록 권한 확인. 수집 출처와 목적별 동의 저장.

시작일 · 1회
STEP 02

개인별 평소 기록

걸음·위치·수면의 관찰 가능일을 축적. 동일 음성·인지과제 반복, 가족 주간 확인. 미수집일을 0으로 채우지 않고 이유를 표시.

1~14일 · 기준선 준비
STEP 03

최근 변화 · 동시 신호

개인 지표별 평소 범위와 최근 관측값 비교. 관찰일이 부족하면 판정을 보류. 수면·이동·활동·음성·인지 신호의 동시 변화를 확인.

15~28일 · 지속 관찰
STEP 04

가족 확인 · 상담 리포트

누가 무엇을 언제부터 느꼈는지 추가 확인. 변화 시작·정도·지속기간, 사용 장치, 실제 관찰일·누락을 함께 표시한 상담준비 리포트 생성.

28일 차 · 비진단 결과
현재 변화감지 코드의 운영상 조건
  • 등록 뒤 14일 경과 후 개인 기준선 준비 여부를 검사합니다.
  • 해당 지표의 기준선 기록이 실제 5일 이상, 최근 3일 중 관찰이 2일 이상인 경우에만 운영상 변화 판정 조건을 검토합니다.
  • 기준을 만족하지 않으면 데이터 부족·미수집으로 표시합니다. 이것은 임상 진단 성능을 검증한 규칙이 아닙니다.
  • 첫 실증 제안: 20가족 × 4주. 모집·동의·수집 성공률·분석 가능일·가족 확인·리포트까지 실제 측정해야 완료로 판정합니다.

데이터 저장에서 반드시 보존할 정보

가명 사용자 ID · 신호 종류 · 측정값/단위 · 수집 일시 · 기기/플랫폼 · 측정 제공자 · 앱/분석버전 · 유효 여부 · 누락 사유 · 목적별 동의 · 가족/기관 확인 수준을 이벤트에 연결합니다. 원자료와 계산한 파생 지표는 구분하고, 서버가 받은 날짜만으로 24시간 센싱을 증명하지 않습니다.

KIMSE / AI

AI — 실제 적용과 도입 계획을 구분합니다

중요한 것은 모델 이름이 아니라 개인별 변화 확인, 가족의 대응, 기관의 업무 효용입니다. 어떤 AI가 실제로 가동되는지는 별도 검증합니다.

현재 확인된 분석

규칙 기반 분석 · 음향 특징 · CAIDE 점수

14일 기준선과 최근 3일 관찰 비교, Web Audio 음향 특징 추출, CAIDE Model 1 점수 합산은 소스코드에 존재합니다. 이는 학습된 치매 예측 AI가 아닙니다.

AI 적용 후보 · 검증 대기

음성 언어특징 · 개인화 복수 신호 · 설명 가능한 결과

사용할 모델·실제 학습자료·정확도·운영비·동의 요건을 검증한 뒤 확정합니다. 현재 상용 AI 서비스나 특정 학습모델을 사용 중이라고 주장하지 않습니다.

실제 모델 도입 여부와 검증 지표는 이 구역에 추후 확정합니다. 자체 진단이나 임상 예측 성능을 의미하지 않습니다.

워치 건강기록 · 의료기관 데이터 교환

Health Connect / HealthKit 자동 수면·심박 수집은 미구현입니다. FHIR 전송 후보·기관 연계 코드는 실제 기관 승인·연결 완료와 구분합니다.

기종·권한·측정 조건·연동비용·결측에 따라 확보 가능한 데이터가 달라집니다. 구현 상태·제품 효용은 이후 구체화합니다.
